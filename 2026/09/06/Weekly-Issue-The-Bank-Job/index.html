尽职编程：AI Coding 时代的个体产出差异的来源

但是我相信每个人的社交圈都会存在一种特能帮你办成事的能人，在古代，他们有另一种名字，叫做乡绅或者师爷，他们的工作就是两个字「办事」。需要注意的是，这类人自己往往并没有具体的专业知识，事情也多半不是他们自己执行的，但是他们就是有能力让别人高高兴兴把事情办成了。

这时候，非常依赖人在其中多思考，多反问 AI，更重要的是，虽然代码不是你写的，但是你要能够回答得出在技术评审的时候别人的提出 —— 这是我认为的达到了「尽职编程」的标准。

我们和 AI 的区别在于，我们想把事情干成，AI 只想让这个对话完成，而干成事情的能力，在历史的长河里一直是稀缺品，从来没有因为工具的进步而被取代过。

Well, note how above I carefully said that the “vast majority” of workflows will work the same with Podman as with Docker. The truth is that not all workflows can be transparently switched over.

我不太同意这篇文章中的建议，大多数时候为了安全，我们会选择忍受一些麻烦，但是 rootless 真的会让你遇到很多你同事不会遇到的问题，把时间投入到这里可能不太值当。当同事都在用 Linux 时，你用 Windows 就会遇到些问题；当同事用 Docker 时，你用 Podman 就会遇到些问题；当同事用 root 用户时，你用普通用户就会遇到些问题。都是惨痛回忆，我知道已经成为 routine 的东西可能不是最佳实践，但是最好别折腾。

开发一款软件，或是建造一座迷宫

我相信，在不远的将来，《织梦岛》或许会再次重置，任何软件也都可能被更快、更好、内存管理更安全的某种编程语言重写，但《织梦岛》中的每个迷宫会永远存在下去，软件里的每个由虚拟概念组成的“迷宫”也会同样存续。

我也同样相信，就像 Agent 无法独自开发出《塞尔达传说》，优秀的软件也同样无法在缺少人类掌舵的情况全自动生长出来。软件开发的未来，或许在于把专属于人类的每一滴创造力，都毫无保留地投入到“迷宫建造”中。愿我们关注每一个概念，对探索迷宫的玩家们感同身受；愿我们在“根本问题”上毫不妥协，创造出能跨越时间存在的深度价值。
